# テストスケジュール — YCCMS

> テストマイルストーンと Epic ごとのテスト WBS。Epic ID は `project/01_management/schedule.md` §3 をそのまま引き継ぐ（テスト側で振り直さない）。
> 日付は `schedule.md`（ベースライン案 v0.1）のマイルストーンとスプリント（2 週間）から算出。`schedule.md` の確定に合わせて見直す。

## 1. 前提

| AT-ID | 前提 | 成り立たない場合の影響 |
| --- | --- | --- |
| AT-001 | 各 Epic の実装と UT は、`schedule.md` §3 の Epic 終了日までに完了する（ストーリー DoD 達成） | 当該 Epic の IT（E-xx-T01〜T03）が同じ日数だけ後ろ倒しになる |
| AT-002 | Epic ごとの IT は、Epic 終了の翌スプリント（2 週間）で実施する。目安：ケース作成 3 営業日 → 実行 5 営業日、不具合修正は実行 2 日目から翌スプリント末まで（1 週間 = 5 営業日で計算） | 不具合が収束しない場合、次スプリントの開発容量を圧迫する |
| AT-003 | IT はローカル開発環境（Supabase ローカル＋RFP フィクスチャのシード）で実施する（ADR-006） | 環境差異による不具合が ST で初めて見つかる可能性がある |
| AT-004 | ST 開始（2027-03-15）までに本番同等の ST 環境と性能用データ（出荷明細 30 万件＋温度 250 万件）が準備される | 性能・BCP テストが実施できず、M-06（ST 完了）が遅延する |
| AT-005 | 仕様未確定の Epic（E-09〜E-13）は、仕様確定後に IT の日程を設定する。全 Epic 結合テスト（2027-03-01〜03-12）開始までに各 Epic の IT が完了している | 全 Epic 結合テストと ST が遅延する |
| AT-006 | 外部連携（ERP、地図サービス、IdP、メールリレー）の検証環境が、該当 Epic の IT 開始までに提供される | 連携部分のみスタブで検証し、実接続の確認は ST に持ち越す |
| AT-007 | UAT 環境とマスキング済みデータが UAT 開始（2027-04-05）までに準備される | UAT 開始が遅延し、M-08・M-10（本稼働 2027-06-01）に影響する |
