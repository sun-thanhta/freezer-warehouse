## 2. ユーザーストーリー

品質管理担当（qa）として、ロット番号や牛の個体識別番号から、そのロットを受け取った全顧客と、仕入先・入荷伝票・入荷時品温までを一度に辿りたい。なぜなら、リコールや行政からの照会があったとき、対象顧客と出所を短時間で漏れなく特定できなければ、被害と信用失墜が拡大するからだ。

## 3. 背景・目的

- YCCMS の 4 つの保証の一つが「ロットから顧客へ、顧客からロットへ辿れること」であり、米（産地・取引）と牛（個体識別番号 10 桁）は法定義務である（米トレーサビリティ法・牛トレーサビリティ法、BR-TRACE-01/02）。その他の SKU は社内ロット（BR-TRACE-03）。
- 順方向トレース：ロット → そのロットを受け取った全顧客（リコール時に使用）。逆方向トレース：顧客 → 受け取ったロット → 仕入先 → 入荷伝票。
- 目標設計では、法定 ID を型付きで検索可能にし（DR-TRACE-01、`lot_regulated_ids`）、リンクの途切れ（入荷伝票のないロット等）を明示し、3 年分のデータで 60 秒以内に応答する（NFR-PERF-02）。
- 本ストーリーはトレース画面（SCR-27、URL `/trace`）と `GET /api/trace`（A20）を実装する。読取専用である。

## 4. 対象ユーザー

| ロール | 本ストーリーでの利用 |
| --- | --- |
| qa（品質管理） | 主利用者。リコール・照会時に順方向トレースで対象顧客を特定する |
| manager（倉庫管理者） | 顧客苦情時に逆方向トレースで出所を確認する |
| sales（営業・CS） | 顧客からの問い合わせに対し、納品ロットと仕入先を回答する |
| auditor（監査） | 法定トレースの証跡確認 |
| warehouse / admin | 閲覧のみ |

全ロールが閲覧可能（画面権限表 S12：全ロール R）。書込操作はない。

## 5. スコープ

**対象範囲**

- 検索条件：
  - 順方向：ロット番号（必須）＋ SKU（任意）。trim 後、大文字小文字を区別せず完全一致（`%`・`_`・`\` はエスケープしワイルドカードにしない）。
  - 順方向（法定 ID）：牛の個体識別番号・米の産地／取引による検索（`lot_regulated_ids` の `(id_type, value)`）。例：「個体識別番号 1408123456 の全ロット」。
  - 逆方向：顧客の選択（コード・名称）。選択すると即時検索。
- ロット情報カード（順方向のみ）：仕入先、入荷伝票（`/inbound/{id}` へのリンク）・入荷時品温（伝票のないロットは「—」）、製造日 → 期限、法定 ID とレーンのバッジ（牛／米／社内）、入荷数量／現在庫。
- 納品一覧：見出し「このロットを受け取った顧客」／「この顧客が受け取ったロット」。列：納品日時（順方向は古い順、逆方向は新しい順）、顧客（納品先）、オーダー（`/outbound/{id}` へのリンク）、SKU（法定レーンなら「牛」「米」バッジ）、ロット／法定 ID、仕入先 ← 入荷伝票（入荷日）、数量。
- リンク途切れの明示：入荷伝票のないロット（移行ロット等）、オーダーのない納品を「リンク途切れ」として表示する（FE-33）。
- 牛の個体識別番号が 9 桁で業務レビュー中のロットは「業務レビュー中」バッジを表示し、番号を補完・丸めない。
- ページングと索引（`delivery_history(lot_id)`、`(customer_id, delivered_at)`、`lot_regulated_ids(id_type, value)`）。
- 画面状態：初期／検索中「トレース中…」／順方向／逆方向／空「関連する納品はありません。」／エラー（目標設計では再試行ボタンあり）。

**対象外**

- リコールケースの作成と数量照合（E-07-S02）、リコール通知（E-07-S03）。結果画面からの「リコールケース作成」ボタンも E-07-S02 で追加する。
- 入荷時の法定 ID の登録・検証（E-03-S03）。
- 顧客別納品履歴画面（E-02-S05）、監査エクスポート（E-08-S03）。

## 6. 主要業務フロー

**正常フロー（順方向）**

1. qa が `/trace` を開き、ロット番号に「LOT-CHI002-C」を入力して「順方向トレース」を押す。
2. 画面が `GET /api/trace?lot=LOT-CHI002-C` を呼ぶ。BFF はユーザー JWT でロット・仕入先・入荷伝票・入荷明細・法定 ID・納品履歴を結合して返す（`{ mode: 'forward', lot, deliveries[] }`）。
3. ロット情報カードと「このロットを受け取った顧客」（CUS-003 ほか、古い順）が表示される。
4. qa は一覧から対象顧客とオーダーを特定し、必要ならオーダー・入荷伝票へ遷移する。

**正常フロー（逆方向）**

1. sales が顧客「CUS-003」を選ぶ → `GET /api/trace?customer={id}`。
2. 「この顧客が受け取ったロット」が新しい順に、仕入先 ← 入荷伝票（入荷日）付きで表示される。

**代替・例外フロー**

- 条件なしで API を呼ぶ：400「ロット番号（順方向）を入力するか、顧客（逆方向）を選択してください」。
- ロットが見つからない：404「ロット "{lot}" が見つかりません」。
- 同じロット番号が複数 SKU に存在し SKU 未指定：409「ロット番号 "{lot}" は複数の SKU に存在します。SKU を指定してください。」（`lots` は `(product_id, lot_no)` で一意のため）。
- 納品実績がない：空状態を表示。
- 入荷伝票のないロット（例：移行ロット LOT-FRO001-X）：入荷伝票・入荷時品温を「—」とし、「リンク途切れ：入荷伝票なし」を表示。
- 未ログイン 401、ロール未付与 403、DB 接続不可 503。
- [ASSUMPTION] 逆方向トレースには納品日の期間指定（既定：直近 1 年、最大 3 年）を設け、1 ページ 100 件でページングする。
- [ASSUMPTION] 法定 ID の検索は完全一致（牛は数字のみ、ハイフン等は除去して比較）。業務レビュー中の 9 桁番号も検索対象に含め、バッジで区別する。

## 8. 技術的制約・非機能面の考慮

- NFR-PERF-02：3 年分（出荷明細 30 万件＋温度測定 250 万件）でトレース ≤ 60 秒。索引 `delivery_history(lot_id)`、`(customer_id, delivered_at)`、`lot_regulated_ids(id_type, value)` を使い、件数が数百万行を超える場合は年単位のパーティションを検討（アーキテクチャ §2.9）。D-18 の索引不足を作らない。
- NFR-PERF-01：通常の検索は p95 ≤ 2 秒。
- ADR-002：ブラウザから DB を直接呼ばない。RLS（ADR-001）で読取のみ。
- 入力のエスケープ：ロット番号の `%`・`_`・`\` をエスケープし、LIKE のワイルドカード検索にしない。
- NFR-LOC-01：日本語・JST。NFR-ACC-01：レーンのバッジは文言付き。
- ADR-006：ローカル Supabase で開発。NFR-PERF-02 のデータ量での測定はクラウド環境（P5、NFR ワークストリーム）まで実施できない（DoD D-010 と ADR-006 の矛盾として管理）。

## 9. 受入基準

- [ ] Given シード（R-06）、When LOT-CHI002-C で順方向トレース、Then ロット情報カード（仕入先・入荷伝票・入荷時品温・製造日 → 期限・入荷数量／在庫）と、CUS-003 を含む受領顧客が古い順に表示される。（E2E）
- [ ] CUS-003 で逆方向トレースすると、受領ロットが新しい順に「仕入先 ← 入荷伝票（入荷日）」付きで表示される。（E2E）
- [ ] 牛（CHI-001）の 10 桁個体識別番号で検索すると、その番号を持つ全ロットと納品先が表示され、「牛」バッジが付く。米（AMB-001）のロットでは産地と取引が別項目で表示される。（E2E＋pgTAP）
- [ ] 9 桁の個体識別番号を持つロットは「業務レビュー中」と表示され、番号が補完・丸められていない。（E2E）
- [ ] ロット番号は大文字小文字を区別せず完全一致し、`%` や `_` を含む入力がワイルドカードとして扱われない。（統合テスト）
- [ ] 同じロット番号が複数 SKU にある場合、SKU 未指定で 409、SKU 指定で 1 件に絞られる。条件なしは 400、該当なしは 404。（統合テスト）
- [ ] 入荷伝票のない移行ロット（LOT-FRO001-X）は入荷伝票を「—」とし「リンク途切れ」を表示する。（E2E）
- [ ] 順方向・逆方向の実行計画が上記索引を使う（`EXPLAIN` で全件走査がない）。NFR-PERF-02 データ量での ≤ 60 秒は NFR ワークストリームで測定する。（pgTAP／性能テスト）
- [ ] 全ロール（warehouse・manager・qa・sales・admin・auditor）が閲覧でき、未ログインは 401。（E2E＋統合テスト）
- [ ] DoD D-005（トレース 3 レーン、ACC-TRC-01 のうちトレース部分）と D-010（3 年トレース ≤ 60 秒）の証跡を残す。
